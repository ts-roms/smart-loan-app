# Gap Matrix — §9 / §86-E

The eleven-column matrix the brief specifies. `modernization-gap-analysis.md`
is the prose version with the reasoning; this is the tabulated one, and it
supersedes that file's tables where they disagree on column count.

**Counts are measured, not estimated.** Endpoint counts come from
`app.{get,post,patch,put,delete}` registrations per feature folder; pages from
`<Route path=…>` in `apps/web/src/App.tsx`; tables from `model` declarations in
`schema.prisma`.

Status vocabulary and priorities are the brief's own (§9, §76).

moved within the EXISTS bucket to NEEDS HARDENING. The table also carried a
pre-existing off-by-one: PARTIAL was recorded as 2 against 3 actual rows, so
removing OpenAPI from it lands at 2 legitimately rather than 1.

**All five P0s identified at Phase 0 are now closed**, and so is every P1 that
engineering could close on its own. Decision-rule versioning, the standing
reconciliation job and frontend test coverage all shipped; the
`Contribution`/`SavingsTransaction` FK change is the remaining schema item.

**Nothing is MISSING and nothing is DANGEROUS any more.** The last
DANGEROUS row is closed, though not the way it was written: it named
`Contribution`/`SavingsTransaction`, and those had already been fixed by
`20260811160000_coop_money_restrict`. **The row was stale, and the batch briefs
that kept scheduling it were reading the matrix rather than the schema.** The
class of problem was real and wider than the row — ten more relations reached
money on delete, and all ten are now `Restrict`.

The lesson is recorded rather than quietly fixed: recounting statuses is not
the same as re-reading rows against the code. A row can be accurate about a
risk and wrong about whether it still exists.

**And it happened again — three more times, in both directions.** The 14 Aug
phase verification (`phase-verification.md`) found the OpenAPI row still claiming
"112 of 337, coverage 33%" when the ratchet test has pinned 328 of 339 for some
time — and `roadmap.md` step 3.4 already said so, meaning **the two trackers
contradicted each other and nobody reconciled them**. The CSP row failed the same
way for a subtler reason: it quoted `contentSecurityPolicy: false` from
`app.ts:191` — which is real, and is a deliberate helmet opt-out — while missing
the `onSend` hook fifteen lines below that sets a strict policy on every JSON
response. **A citation can be literally accurate and still describe the opposite
of what the code does.** In the other direction, the AI-assistant row said the
§51 audit trail was "not stored" when four of its seven fields are — the first
stale row found to be _pessimistic_ rather than optimistic.

That makes eight. The pattern is now specific enough to name: rows go stale when
they record a _symptom string_ (a flag, a count, a file name) rather than a
_behaviour_, because the string survives the fix that changes the behaviour.

**Nothing is DANGEROUS at row level, but one sub-item is.** Re-running an ECL
period double-posts the provision movement to the GL, because `postIfAbsent` keys
on a freshly-minted `EclRun.id` — while the UI's confirmation dialog tells the
operator it is "idempotent — safe to re-run". It is folded into the IFRS-9 row
above rather than given its own row, which is exactly the kind of averaging-away
this matrix keeps getting caught by; it is written out in full in
`phase-verification.md` §35 and carries a roadmap line of its own.

**No row is MISSING outright any more.** Object storage was the last one, and it
turned out to be mis-scoped rather than blocked: credentials block _running_
against a bucket, not building the seam. `libs/storage` ships with local disk as
the default and an S3-compatible adapter behind one environment variable, so
adopting a bucket is now a config change plus a file copy — the roadmap's
flagged "high risk — data migration of existing files" does not exist, because
storage keys are the stored URL minus `/uploads/` and no schema references them.

Next.js is PARTIAL: the `apps/marketing-next` pilot answers what the migration
costs, while the three SPAs remain Vite by decision, not by omission.
